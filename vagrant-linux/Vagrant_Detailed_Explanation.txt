VAGRANT DETAILED EXPLANATION
=============================

1. INTRODUCTION
---------------
Vagrant is an open-source tool developed by HashiCorp for building and managing virtualized development environments.
It automates the creation and configuration of virtual machines (VMs) for consistent, portable development setups.

2. WHY USE VAGRANT
------------------
- Avoid the “works on my machine” problem.
- Quickly spin up identical environments.
- Automate configuration and provisioning.
- Test infrastructure as code.

Common use cases:
- Isolated development environments.
- Local testing before deploying to cloud.
- CI/CD pipeline testing.

3. ARCHITECTURE
---------------
Components:
1. Vagrant CLI - Command line interface.
2. Vagrantfile - Configuration file written in Ruby syntax.
3. Providers - Virtualization backends (VirtualBox, VMware, Hyper-V, Docker, AWS, etc.).
4. Boxes - Pre-packaged base OS images.
5. Provisioners - Automate setup using Shell, Ansible, Chef, Puppet, etc.

4. BOXES
--------
A box is a pre-built base image used by Vagrant to launch environments.

Examples:
    vagrant box list
    vagrant box add ubuntu/focal64
    vagrant box remove ubuntu/focal64

5. VAGRANTFILE STRUCTURE
------------------------
Example:

Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/focal64"
  config.vm.hostname = "my-vagrant-vm"
  config.vm.network "private_network", ip: "192.168.56.10"
  config.vm.synced_folder "./app", "/home/vagrant/app"
  config.vm.provision "shell", inline: <<-SHELL
    sudo apt-get update
    sudo apt-get install -y nginx
  SHELL
end

6. WORKFLOW
-----------
1. Initialize:  vagrant init ubuntu/focal64
2. Start VM:    vagrant up
3. SSH Access:  vagrant ssh
4. Suspend VM:  vagrant suspend
5. Resume VM:   vagrant resume
6. Stop VM:     vagrant halt
7. Destroy VM:  vagrant destroy
8. Reprovision: vagrant reload --provision

7. NETWORKING
-------------
a) Port Forwarding
   config.vm.network "forwarded_port", guest: 80, host: 8080

b) Private Network
   config.vm.network "private_network", ip: "192.168.56.10"

c) Public Network
   config.vm.network "public_network"

8. PROVISIONING
---------------
Provisioning automates the setup of software and dependencies inside the VM.

Types:
- Shell Script
  config.vm.provision "shell", path: "setup.sh"
- Inline Script
  config.vm.provision "shell", inline: "sudo apt update && sudo apt install -y nginx"
- Ansible
  config.vm.provision "ansible" do |ansible|
    ansible.playbook = "playbook.yml"
  end

9. SYNCED FOLDERS
-----------------
Syncs files between host and guest.
Example:
  config.vm.synced_folder "./code", "/home/vagrant/code"

10. MULTI-MACHINE SETUP
-----------------------
Example:

Vagrant.configure("2") do |config|
  config.vm.define "web" do |web|
    web.vm.box = "ubuntu/focal64"
    web.vm.network "private_network", ip: "192.168.56.11"
  end

  config.vm.define "db" do |db|
    db.vm.box = "ubuntu/focal64"
    db.vm.network "private_network", ip: "192.168.56.12"
  end
end

Commands:
  vagrant up web
  vagrant up db
  vagrant ssh web
  vagrant ssh db

11. PLUGINS
-----------
Vagrant plugins extend functionality.

Examples:
  vagrant plugin install vagrant-aws
  vagrant plugin install vagrant-docker-compose
  vagrant plugin list

12. COMMON COMMANDS
-------------------
| Command                  | Description                         |
|---------------------------|-------------------------------------|
| vagrant init              | Initialize new environment          |
| vagrant up                | Start VM                            |
| vagrant ssh               | SSH into VM                         |
| vagrant halt              | Stop VM                             |
| vagrant destroy           | Remove VM                           |
| vagrant reload            | Reload configuration                |
| vagrant box list          | List installed boxes                |
| vagrant provision         | Run provisioning scripts again      |
| vagrant snapshot save     | Save snapshot                       |
| vagrant snapshot restore  | Restore snapshot                    |

13. ADVANTAGES
--------------
- Reproducible environments
- Automation via provisioning
- Cross-platform support
- Seamless collaboration
- Simple rollback via snapshots

14. LIMITATIONS
---------------
- Slower than containers
- Requires virtualization hardware support
- Consumes more system resources

15. VAGRANT VS DOCKER
----------------------
| Feature        | Vagrant (VMs)     | Docker (Containers)     |
|----------------|------------------|--------------------------|
| Virtualization | Full OS           | Shared kernel            |
| Speed          | Slower            | Faster                   |
| Use Case       | OS-level testing  | Microservices, CI/CD     |
| Resource Usage | High              | Low                      |

16. SUMMARY
-----------
Vagrant simplifies virtual environment management by automating VM creation, configuration, and provisioning.
It is ideal for development and testing environments where reproducibility and consistency are critical.
