GITLAB COMPLETE DETAILS

1. SETUP DETAILS
-----------------
- GitLab is a web-based DevOps lifecycle tool providing Git repository management, CI/CD pipelines, issue tracking, and more.
- It can be self-hosted (GitLab CE/EE) or cloud-hosted (GitLab.com).

SETUP STEPS:
1. Install GitLab (Self-hosted) or create an account on GitLab.com.
2. Create a new project/repository.
3. Enable CI/CD by adding a `.gitlab-ci.yml` file in the project root.
4. Configure GitLab Runners (agents that execute jobs). Types:
   - Shared runners: provided by GitLab instance.
   - Specific runners: registered manually for your project or group.

Register a new runner (self-hosted example):
```bash
sudo gitlab-runner register
# Provide GitLab URL and registration token from project Settings > CI/CD > Runners
```
5. Once registered, you can use tags to assign specific runners to jobs.

2. PIPELINE DETAILS
-------------------
- GitLab pipelines are defined in `.gitlab-ci.yml`.
- A pipeline consists of **stages** (e.g., build, test, deploy), each containing **jobs**.

Example:
```yaml
stages:
  - build
  - test
  - deploy

build-job:
  stage: build
  script:
    - echo "Building application"
    - mvn package

test-job:
  stage: test
  script:
    - echo "Running tests"
    - mvn test

deploy-job:
  stage: deploy
  script:
    - echo "Deploying application"
  only:
    - main
```

Each commit or merge request triggers a new pipeline execution (if defined).

3. VARIABLES AND SECRETS
-------------------------
- **Variables** allow dynamic configuration inside pipelines.
- **Secrets** (like passwords or tokens) are stored securely and injected into pipelines.

Define variables in `.gitlab-ci.yml`:
```yaml
variables:
  APP_ENV: "production"
  DOCKER_IMAGE: "myapp:latest"
```

Define sensitive variables in:
- GitLab UI → Project → Settings → CI/CD → Variables → Add variable.
- They are masked and hidden in logs.

Use in script:
```yaml
script:
  - echo "Deploying to $APP_ENV environment"
  - docker login -u $CI_REGISTRY_USER -p $CI_REGISTRY_PASSWORD $CI_REGISTRY
```

Predefined variables:
- `$CI_PROJECT_NAME` – project name
- `$CI_COMMIT_SHA` – current commit SHA
- `$CI_PIPELINE_ID` – pipeline ID
- `$CI_JOB_STAGE` – current job stage

4. TRIGGERS AND RULES
----------------------
- **Rules** determine when jobs run (replaces `only`/`except`).
- **Triggers** enable pipelines to start from external events or other pipelines.

Example using rules:
```yaml
deploy-job:
  stage: deploy
  script: echo "Deploying..."
  rules:
    - if: '$CI_COMMIT_BRANCH == "main"'
    - when: manual
    - allow_failure: false
```

Triggering pipelines manually or via API:
```bash
curl --request POST      --form token=TRIGGER_TOKEN      --form ref=main      https://gitlab.com/api/v4/projects/1234/trigger/pipeline
```

You can also use **trigger jobs** to start downstream pipelines:
```yaml
trigger-deploy:
  stage: deploy
  trigger:
    project: my-org/deploy-repo
    branch: main
```

5. SECURITY AND ARTIFACTS
--------------------------
**Security:**
- GitLab CI integrates with container scanning, SAST, DAST, dependency scanning, and license compliance.
- Configure in `.gitlab-ci.yml` using templates like:
```yaml
include:
  - template: Security/SAST.gitlab-ci.yml
  - template: Security/Dependency-Scanning.gitlab-ci.yml
```

**Artifacts:**
- Artifacts are files generated by a job and passed to later stages or available for download.

Example:
```yaml
build-job:
  stage: build
  script:
    - mvn package
  artifacts:
    paths:
      - target/*.jar
    expire_in: 1 week
```

Artifacts can be browsed or downloaded from the GitLab UI under Job → Artifacts.

6. BUILD AND PUBLISH DOCKER STAGE
----------------------------------
To build and push Docker images to GitLab Container Registry:

**Setup:**
- Ensure GitLab Container Registry is enabled in your project (Settings → Packages & Registries → Container Registry).
- Define CI variables for registry authentication (`CI_REGISTRY_USER`, `CI_REGISTRY_PASSWORD`).

**Example .gitlab-ci.yml:**
```yaml
stages:
  - build
  - push

variables:
  IMAGE_NAME: "$CI_REGISTRY_IMAGE:$CI_COMMIT_SHORT_SHA"

build-image:
  stage: build
  image: docker:latest
  services:
    - docker:dind
  script:
    - docker build -t $IMAGE_NAME .
    - docker images

push-image:
  stage: push
  image: docker:latest
  services:
    - docker:dind
  script:
    - echo "$CI_REGISTRY_PASSWORD" | docker login -u "$CI_REGISTRY_USER" $CI_REGISTRY --password-stdin
    - docker push $IMAGE_NAME
  only:
    - main
```

✅ This builds a Docker image for every commit and pushes it to the GitLab Container Registry.

7. BEST PRACTICES
------------------
- Use **rules** instead of deprecated `only/except`.
- Mask and protect sensitive variables.
- Use **include templates** for security scans.
- Use caching for dependencies to speed up builds.
- Tag runners appropriately for specific jobs.
- Store build outputs as **artifacts** instead of manually archiving.
